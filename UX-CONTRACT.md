# UI behavior contract

User request 2026-10-28: owners delete their listings from MemberListings, and ADMIN/SUPER_ADMIN delete any listing from AdminListings; MODERATOR does not see the manager delete action. Shared DeleteListingDialog uses the existing Radix Modal contract, initially focuses Cancel, names the listing, explains that reposting requires a new listing, and requires a reason for a manager deletion. Dismissal and duplicate submission are blocked while busy. Errors and entered reasons remain in the dialog for retry. Success closes the dialog, refreshes list/counts, and steps back one page if its last item was deleted. Server authorization, version conflicts, soft deletion, private reports/media and notification behavior are documented in docs/API.md. Evidence: tests/listing-deletion.test.ts and tests/e2e/listing-deletion.spec.ts.

Business source: PRODUCT.md (user supplied specification), server/services and Prisma schema. Publication requires approval; all private fields and contacts remain private by default; there are no payments.

Search/filter/sort/page live in URL. Search commits on submit, preserving IME input and avoiding request races; clear immediately submits empty query. Data requests are abortable and ignore superseded responses. Lists use bounded server pagination.

Admin account creation and social settings are owned by src/pages/admin-extra.tsx using shared fields, Modal, PasswordField, FormMessage and Toast. Creating accounts requires an acting administrator password and confirmation for the new password; ADMIN sees only MEMBER, SUPER_ADMIN sees all roles, and server authorization is authoritative. Failed submits preserve values and modal dismissal clears secrets. Social links use stable UUIDs and HTTPS-only fields; enabled links appear at /contact and the footer. The main .container.nav-inner contains ติดต่อเรา. Evidence: tests/admin-creation-social.test.ts and tests/e2e/admin-tools.spec.ts.

Registration availability belongs to SettingsForm and the native checkbox with role=switch, labeled เปิดรับสมัครสมาชิก. It is committed by บันทึกการตั้งค่า, persists after reload, and does not disable existing logins. AuthPage waits for settings before rendering signup, displays an explicit closed state/retry for errors, and refreshes settings after a server-side 403 for a stale form. Server validation owns all writes. ImageUpload explains automatic WebP optimization and reports upload/compression progress; processing is authoritative on the server before persistence. Verification is in tests/registration-settings.test.ts, tests/image-optimization.test.ts, and tests/e2e/settings-upload.spec.ts.

Support conversations are owned by `src/pages/support.tsx`, using shared Field/Textarea/Select/Button/FormMessage/Pagination and UnsavedGuard. Member routes are `/dashboard/support`, `/new`, and `/:id`; manager routes are `/admin/support` and `/:id`. New-topic and reply drafts survive validation/network/version errors and conversation refresh; successful sends clear only after server acceptance. Draft request UUIDs prevent duplicate messages on retry. Loading/error/empty states are explicit, status filter and pagination live in the URL, long text wraps on mobile, and chronological messages identify the sender and time. ADMIN/SUPER_ADMIN may reply/close, owners may reply/reopen. Bell opening fetches fresh notifications and clicking the same thread reloads it without discarding a draft. Runtime evidence is `tests/e2e/support.spec.ts`; API/privacy/concurrency evidence is `tests/support.test.ts`.

Save buttons disable during requests. Errors persist inline, values remain intact. Dialogs use Radix focus trap and restoration. Native confirmation dialogs are prohibited. Passwords are masked with reveal controls. In-app unsaved form navigation uses shared blocker dialog and browser unload protection.

Every page has loading skeleton, retryable error and empty state. Member notifications poll every 30 seconds and mark read only on action. Dates use th-TH, Asia/Bangkok; database times UTC. Editing an approved item makes it pending immediately. Public API and media access enforce this invariant.

Authentication: username + password (minimum 8 characters for new passwords); no email or Google login. Registration keeps entered values on validation errors. Forgot-password links to administrator contact. Existing users keep their username and password. Password changes require the current password and revoke all sessions.

User request 2026-10-26: multiple popup announcements rotate every five seconds in one shared Modal. Canonical owner: src/components/popup-slideshow.tsx; server eligibility/claim remains authoritative (docs/API.md). Individual delays add ready slides, each slide claims once on first display, and revisits in the open group do not count twice. Prev/next/dots pause autoplay; explicit play resumes. Mouse hover and hidden tabs pause timers; keyboard interaction pauses rotation; reduced-motion starts paused. Closing dismisses the whole group and cancels delayed slides/requests until route or account changes. Expired/unavailable slides are skipped, next-slide network failures preserve the current slide with retry, and announcements never block the page when initial retrieval fails. Navigation/account changes remount the group so stale responses cannot reopen the previous page's popup.

User request 2026-10-26: listing type is SALE (สำหรับขาย) or SHOW (สำหรับโชว์), defaulting to SALE for existing data. ListingForm uses the shared native Select; SHOW hides price controls and preview/public/member/admin surfaces show the type and ไม่เปิดขาย. Price controls retain unsaved values when toggling within the form, while the server discards prices on SHOW save. API rules are in docs/API.md; type changes follow the existing review and version-conflict workflow. Shared listingTypeLabel/listingPrice in src/types.ts own display wording.

User request 2026-10-26: support more than eight listing images and staff password resets. ImageUpload owns the twelve-image default, ordering and explicit primary-image action; the first stored image is primary (docs/API.md). The public gallery must contain horizontal thumbnail scrolling within its grid column on mobile. AdminUsers uses shared Modal/PasswordField/FormMessage/Toast for resets under docs/SECURITY.md role boundaries. The reset dialog initially focuses Cancel, restores trigger focus on dismissal, preserves input on failure, blocks duplicate submissions/closing during submission, and clears secrets on dismissal. Passwords never appear in toast/audit/response. Shared Modal supports an optional initial-focus selector applied after capturing the opener.
